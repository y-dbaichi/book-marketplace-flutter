\section{Introduction}

\subsection{Project Context}

The growth of e-commerce has transformed how people purchase books. However, this growth has created new challenges for small and independent book sellers who must manage deliveries efficiently. Many vendors struggle with route planning, leading to excessive fuel consumption, extended delivery times, and increased operational costs. Poor delivery logistics also contribute to environmental impact through unnecessary carbon emissions.

This project addresses these challenges by developing a comprehensive book marketplace platform that integrates Geographic Information Systems (GIS) technology for delivery route optimization. The solution helps sellers reduce costs and delivery times while providing buyers with a convenient online shopping experience.

\subsection{Project Objectives}

The main objectives of this project are:

\begin{itemize}
    \item Create an online marketplace where buyers can browse and order books
    \item Enable precise delivery location selection using interactive maps
    \item Provide sellers with tools to optimize delivery routes using GIS algorithms
    \item Reduce delivery distance and time through intelligent route planning
    \item Integrate professional navigation tools for real-world delivery execution
    \item Use open-source technologies to ensure sustainability and accessibility
\end{itemize}

\subsection{Project Structure}

The platform is built on a dual-application architecture:

\textbf{Web Application (React):} Serves both buyers and sellers for account management, book browsing, ordering, and catalog management. Buyers use an interactive map with geocoding support to specify their exact delivery location.

\textbf{Mobile Application (Flutter):} Exclusively designed for sellers to manage deliveries on the go. This app focuses on the core GIS functionality: route optimization, turn-by-turn navigation, and delivery tracking.

This separation allows each platform to be optimized for its specific use case while maintaining a unified backend system.

\section{Context and Background}

\subsection{The Delivery Challenge}

Last-mile delivery represents one of the most expensive and inefficient parts of the logistics chain. For small book sellers operating in urban areas, visiting multiple delivery points without proper route planning can result in:

\begin{itemize}
    \item Wasted fuel from inefficient routing
    \item Increased delivery time affecting customer satisfaction
    \item Higher operational costs reducing profit margins
    \item Greater environmental impact from unnecessary travel
    \item Driver fatigue from longer routes
\end{itemize}

Traditional approaches involve delivering books in the order they were received or based on arbitrary grouping. This project demonstrates how applying GIS algorithms can significantly improve efficiency.

\subsection{Understanding Geographic Information Systems}

Geographic Information Systems are technologies that capture, store, analyze, and visualize geographic data. In the context of this project, GIS enables several critical capabilities:

\textbf{Location Representation:} The system stores delivery locations using the WGS84 coordinate system, which is the standard used by GPS satellites worldwide. Each delivery point is represented by latitude and longitude coordinates with high precision.

\textbf{Distance Calculation:} Calculating distances between GPS coordinates requires accounting for Earth's curvature. The system uses the Haversine distance formula, which calculates the shortest distance between two points on a sphere. This provides accurate distance measurements for route optimization.

\textbf{Route Optimization:} The Traveling Salesman Problem is a classic optimization challenge: given multiple points to visit, what is the shortest possible route that visits each point exactly once? This project implements the Nearest Neighbor algorithm, a greedy approach that builds the route by repeatedly choosing the closest unvisited point. While not guaranteed to find the absolute optimal solution, it provides very good results quickly, which is essential for mobile applications.

\textbf{Map Visualization:} The system displays delivery points on OpenStreetMap, a free and open-source mapping platform. Maps use a different projection system called Web Mercator for rendering, but all data storage uses WGS84 for compatibility.

\textbf{Turn-by-Turn Navigation:} After optimizing the delivery sequence, the system uses OpenRouteService API to generate actual road-based routes with detailed navigation instructions. This considers real road networks, one-way streets, and driving regulations.

\section{Functional Requirements}

\subsection{Web Application Features}

\begin{enumerate}

    \item Select delivery location using the interactive map
    \item Search for their address using the geocoding feature, or click directly on the map

The delivery location selection is a critical GIS feature. The MapPicker component allows buyers to:
\begin{itemize}
    \item Type an address and see it located on the map
    \item Click anywhere on the map to set a precise delivery point
    \item View the selected location with a marker
    \item See coordinate information for verification
\end{itemize}

This ensures sellers have accurate delivery locations, which is essential for route optimization.

\textbf{Order Tracking:}

Buyers can view their order history with status information:
\begin{itemize}
    \item Pending: Order received, awaiting seller confirmation
    \item Confirmed: Seller accepted the order, preparing for delivery
    \item Delivered: Order successfully delivered
\end{itemize}

\subsubsection{Seller Functionality on Web}

\textbf{Catalog Management:}

Sellers use the web interface to:
\begin{itemize}
    \item Add new books to their catalog
    \item Upload book cover images
    \item Edit book information (title, author, description, price)
    \item Manage inventory
\end{itemize}

\textbf{Order Management:}

Sellers can:
\begin{itemize}
    \item View all incoming orders
    \item Filter orders by status
    \item See buyer delivery locations on a map
    \item Confirm orders to add them to the delivery queue
\end{itemize}

\subsection{Mobile Application Features (Sellers Only)}

The mobile application is exclusively for sellers and focuses entirely on delivery management.

\subsubsection{Authentication}

Sellers login using credentials created on the web platform. The mobile app does not support registration to maintain security and control. Authentication tokens are stored securely on the device using Flutter Secure Storage.

\subsubsection{Order Viewing and Selection}

The home screen displays all confirmed orders. Each order card shows:
\begin{itemize}
    \item Book title and cover image
    \item Buyer name
    \item Delivery location (address or coordinates)
    \item Order quantity
    \item Total price
\end{itemize}

Sellers select multiple orders for a delivery tour using checkboxes. The selection process considers:
\begin{itemize}
    \item Geographic proximity of delivery points
    \item Time availability
    \item Order priority
\end{itemize}

\subsubsection{Route Calculation Workflow}

Once orders are selected, the route calculation process begins:

\textbf{Step 1 - Starting Point:}

The seller must define a starting location. Two options are available:
\begin{itemize}
    \item Use GPS button to get current location automatically
    \item Tap on the map to manually set a starting point
\end{itemize}

The GPS option uses the device's location services with high accuracy mode to get the seller's actual position within approximately 10 meters.

\textbf{Step 2 - Route Optimization:}

When the seller taps "Calculate Route," the app performs the following:

\begin{enumerate}
    \item Extracts GPS coordinates from all selected orders
    \item Applies the Nearest Neighbor TSP algorithm starting from the defined starting point
    \item Finds the closest unvisited delivery point
    \item Adds it to the route and marks it as visited
    \item Repeats until all delivery points are included
    \item Reorders the order list to match the optimized sequence
\end{enumerate}

This optimization typically reduces total travel distance by 35-40\% compared to visiting delivery points in random order.

\textbf{Step 3 - Route Fetching:}

The optimized sequence of points is sent to OpenRouteService API, which returns:
\begin{itemize}
    \item A polyline representing the actual road route
    \item Total distance for the entire tour
    \item Estimated duration
    \item Turn-by-turn navigation instructions
\end{itemize}

The route is displayed on the map as a blue line connecting all delivery points in order.

\subsubsection{Navigation and Delivery Execution}

\textbf{Viewing Turn-by-Turn Instructions:}

The app displays detailed navigation instructions such as:
\begin{itemize}
    \item "Head north on Avenue Mohammed V"
    \item "Turn right onto Boulevard Moulay Youssef"
    \item "Continue for 2.3 km"
    \item "Turn left onto Rue des Roses"
    \item "Arrive at destination"
\end{itemize}

Each instruction includes distance and direction information.

\textbf{External Navigation:}

For actual driving navigation, sellers tap the "Navigate" button, which offers two options:
\begin{itemize}
    \item Google Maps
    \item Waze
\end{itemize}

The app launches the selected navigation app with all delivery waypoints pre-loaded. This approach leverages professional navigation features including:
\begin{itemize}
    \item Real-time GPS tracking
    \item Live traffic updates
    \item Voice-guided navigation
    \item Automatic rerouting if needed
    \item Offline maps (if downloaded)
\end{itemize}

\textbf{Delivery Confirmation:}

At each delivery point, the seller:
\begin{itemize}
    \item Confirms successful delivery by tapping "Mark as Delivered"
    \item Can add optional notes about the delivery
    \item System updates order status in the database
    \item Progress is tracked showing completed vs remaining deliveries
\end{itemize}

    \item Backend validates request and creates order in database

    \item Seller opens mobile app and views confirmed orders

    \item Device GPS provides coordinates
    \item Seller taps "Calculate Route"

    \item Runs Nearest Neighbor algorithm locally on device
    \item Sends optimized waypoint sequence to OpenRouteService
    \item OpenRouteService returns route geometry and instructions
    \item App displays route on map with distance and time
    \item Seller reviews route and taps "Navigate"
    \item Chooses Google Maps or Waze
    \item External app opens with full route loaded
    \item Seller follows navigation to each delivery point
    \item Marks each order as delivered upon completion
    \item Backend updates order status in database
\end{enumerate}

\section{Conclusion}

This project successfully demonstrates the application of Geographic Information Systems to solve real-world logistics challenges in small business operations. By creating a book marketplace platform with integrated route optimization, we have shown how GIS technology can make delivery operations significantly more efficient.

The dual-platform architecture effectively serves different user needs. The web application provides a familiar e-commerce experience for buyers while giving sellers tools to manage their inventory and orders. The mobile application focuses entirely on delivery optimization, providing sellers with professional-grade route planning and navigation support.

\subsection{Key Achievements}

\textbf{Technical Implementation:}
\begin{itemize}

    \item Integrated multiple GIS technologies: WGS84 coordinates, Haversine distance, OpenStreetMap, Nominatim geocoding, and OpenRouteService routing
    \item Built a complete full-stack application with React, Flutter, and Node.js
    \item Created seamless integration between web and mobile platforms
    \item Implemented secure authentication and data synchronization
\end{itemize}

\textbf{Operational Results:}
\begin{itemize}
    \item Achieved 35-40\% reduction in delivery distance through route optimization
    \item Enabled fast route calculation (under 200ms for 20 points)
    \item Provided accurate location data (10-meter GPS precision)
    \item Created user-friendly interfaces requiring minimal training
\end{itemize}

\textbf{Use of Open-Source Technology:}
\begin{itemize}
    \item Utilized free and open-source GIS services
    \item No licensing costs or vendor lock-in
    \item Sustainable and scalable solution
    \item Community-supported mapping infrastructure
\end{itemize}

\subsection{GIS Concepts Applied}

This project demonstrates practical application of several important GIS concepts:

\textbf{Coordinate Systems:} Understanding and correctly implementing WGS84 for data storage and GPS compatibility.

\textbf{Distance Calculation:} Using Haversine formula to calculate accurate distances on Earth's curved surface.

\textbf{Route Optimization:} Applying the Traveling Salesman Problem and Nearest Neighbor algorithm to minimize travel distance.

\textbf{Map Projections:} Working with different coordinate systems for storage (WGS84) and display (Web Mercator).

\textbf{Geocoding:} Converting between addresses and geographic coordinates for user convenience.

\textbf{Spatial Data Management:} Storing and querying location-based information efficiently.

\subsection{Lessons Learned}

\textbf{Algorithm Trade-offs:} The Nearest Neighbor algorithm provides a good balance between solution quality and computation speed. While more sophisticated TSP algorithms could find slightly better routes, the Nearest Neighbor approach is fast enough for real-time mobile use and provides significant improvements over random routing.

\textbf{External Service Integration:} Leveraging existing professional navigation apps (Google Maps, Waze) rather than building complete navigation from scratch allows the application to provide better user experience while focusing development effort on the core GIS optimization problem.

\textbf{Platform Separation:} Separating web and mobile applications based on user roles and tasks creates a cleaner architecture and better user experience than trying to make a single application serve all purposes.

\textbf{Open-Source Benefits:} Using open-source GIS services and libraries provides flexibility, reduces costs, and ensures the solution remains accessible and sustainable.

\subsection{Future Improvements}

While the current implementation successfully achieves the project objectives, several enhancements could further improve the system:

\textbf{Advanced Routing Algorithms:} Implementing 2-opt or genetic algorithms could improve route quality by an additional 10-15\%, though at the cost of longer calculation times.

\textbf{Real-Time Features:} Adding live GPS tracking during delivery and proximity notifications could enhance the delivery experience.

\textbf{Batch Optimization:} Developing algorithms to group orders by geographic regions automatically could help sellers plan multi-day delivery schedules.

\textbf{Historical Data Analysis:} Tracking delivery patterns over time could help predict optimal delivery times and identify frequently served areas.

\textbf{Offline Support:} Caching map tiles and route data would allow the application to work in areas with poor network connectivity.

By applying GIS technology to the challenge of delivery route optimization, small book sellers can operate more efficiently, reduce costs, and provide better service to their customers.

The success of this implementation shows that even relatively simple GIS algorithms, when properly applied, can produce significant improvements in operational efficiency. The combination of open-source mapping services, modern mobile technology, and classic optimization algorithms creates a solution that is both effective and accessible to small businesses.
